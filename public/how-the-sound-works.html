AUDIOLAB · How it works

The sound,
taken apart

The whole soundscape on the homepage is built with the browser's built-in Web Audio API — no libraries, no audio files, everything generated live. This page rebuilds it one piece at a time. Every box below is real and playable: press the buttons, drag the sliders, move inside the pad. Read the code under each step and you'll be able to explain the homepage end to end.

🔊 Turn your volume to a comfortable level. Audio can only start after you click something — that's a browser rule, explained in Step 1.

The one idea behind everything: a graph

Web Audio is like a modular synth / guitar pedalboard. You create little boxes called nodes (a tone generator, a volume knob, a filter…) and you connect them with virtual patch cables using .connect(). Sound flows left to right until it reaches the speakers.

source→ effects→ destination (speakers)

That's it. Build nodes, connect them, change their values over time. Now let's build the real ones.

STEP 01

The AudioContext — the engine

Everything lives inside one AudioContext. It's the studio that runs the audio clock and owns every node. Browsers block sound until the user interacts (so pages can't blast you on load) — so we create it on a click and "resume" it.

Demo · create the engine
state: not created 
// One context for the whole app. Created on a user gesture (a click).
const ctx = new (window.AudioContext || window.webkitAudioContext)();
// If the browser paused it, wake it up:
if (ctx.state === "suspended") ctx.resume();
ctx.destination; // ← the speakers. Everything ends up here.
STEP 02

An oscillator — one pure tone

An OscillatorNode generates a tone at a frequency (in Hz = pitch). We send it through a GainNode (a volume knob) before the speakers — always, so we can fade smoothly instead of clicking on/off.

Demo · one oscillator → gain → speakers
Frequency · 220 Hz
oscillator→ gain→ speakers 
const osc  = ctx.createOscillator();
const gain = ctx.createGain();
osc.type = "sine";              // sine / square / sawtooth / triangle
osc.frequency.value = 220;      // pitch in Hz
gain.gain.value = 0.2;          // keep it gentle

osc.connect(gain);              // patch cable: osc → gain
gain.connect(ctx.destination);  // patch cable: gain → speakers
osc.start();                    // an oscillator can only be started ONCE

Note: you can't re-start() an oscillator. To play again you build a fresh one. That's why the demo recreates it each time.

STEP 03

Changing values smoothly

If you set gain.value abruptly you hear a click ("zipper noise"). Audio parameters can instead be scheduled to glide. Two tools we use everywhere:

  • setTargetAtTime(target, now, τ) — ease toward a value with time-constant τ. Great for live controls (this is what the mouse uses).
  • exponentialRampToValueAtTime(v, t) — ramp to a value by a deadline. We use it for the 3-second fade-in / fade-out.
Demo · smooth vs. instant
Volume (glides) · 0.20 
// Glide toward the new volume over ~60ms — no click:
gain.gain.setTargetAtTime(newVolume, ctx.currentTime, 0.06);

// Smooth fade to (near) silence over 1.2s. Exponential can't hit 0,
// so we aim at a tiny number:
gain.gain.exponentialRampToValueAtTime(0.0001, ctx.currentTime + 1.2);
STEP 04

The filter + your mouse ⭐

This is the interactive part of the homepage. A BiquadFilterNode set to lowpass removes frequencies above a cutoff — low cutoff = dark/muffled, high cutoff = bright. Its Q (resonance) emphasises frequencies right at the cutoff.

We map the mouse position onto those two knobs:

  • X (left → right) → cutoff frequency
  • Y (top → bottom) → resonance (Q)

Move your pointer inside the pad (drag on touch). A rich sawtooth is playing so the filter is obvious:

Demo · move inside the box to play the filter
cutoff — · Q —
cutoff → ↑ resonance 
const filter = ctx.createBiquadFilter();
filter.type = "lowpass";

// x, y come in as 0..1 from the mouse position on screen.
function aim(x, y) {
  // Exponential map so pitch feels even to the ear (not linear Hz):
  const cutoff = 300 * Math.pow(4500 / 300, x);   // 300 Hz … 4500 Hz
  const q      = 0.5 + (1 - y) * 11.5;            // 0.5 (bottom) … 12 (top)

  // Glide toward the new values so dragging sounds liquid, not steppy:
  const t = ctx.currentTime;
  filter.frequency.setTargetAtTime(cutoff, t, 0.08);
  filter.Q.setTargetAtTime(q, t, 0.08);
}

// On the real page we listen on the whole window while sound is on:
window.addEventListener("pointermove", (e) => {
  aim(e.clientX / window.innerWidth, e.clientY / window.innerHeight);
});

Why Math.pow? Pitch is logarithmic — the gap 100→200 Hz sounds the same size as 1000→2000 Hz. An exponential map makes the left-to-right sweep feel even instead of bunched up at the bottom.

STEP 05

The drone chord — detune & LFOs

The homepage layers four oscillators tuned to an A–E–A–E open fifth (110, 164.81, 220, 329.63 Hz). Two tricks make it feel alive:

  • Detune — each voice is shifted a few cents. Slightly out-of-tune copies beat against each other → shimmer.
  • LFO (Low-Frequency Oscillator) — an oscillator so slow (~0.05 Hz, one cycle every 20s) you don't hear it as a tone; instead it's wired to a gain to slowly swell each voice in and out.
Demo · the breathing chord
4 oscillators · detuned · slow LFO swells 
[110, 164.81, 220, 329.63].forEach((freq, i) => {
  const osc = ctx.createOscillator();
  osc.frequency.value = freq;
  osc.detune.value = (i - 1.5) * 4;        // a few cents apart → beating

  const g = ctx.createGain();
  g.gain.value = 0.2;

  // A very slow oscillator wired into the gain = automatic swells:
  const lfo = ctx.createOscillator();
  lfo.frequency.value = 0.03 + i * 0.017;  // ~one cycle every 20–30s
  const lfoAmt = ctx.createGain();
  lfoAmt.gain.value = 0.1;
  lfo.connect(lfoAmt).connect(g.gain);     // LFO modulates volume

  osc.connect(g).connect(filter);          // into the shared filter
  osc.start(); lfo.start();
});
STEP 06

The oscilloscope — drawing the sound

The green line is not decoration — it's the actual waveform. An AnalyserNode taps the signal and hands us the raw samples; we redraw them onto a <canvas> ~60×/second with requestAnimationFrame. Change the wave shape and watch the line change:

Demo · live waveform
Wave shape 
const analyser = ctx.createAnalyser();
analyser.fftSize = 2048;            // how many samples we read
master.connect(analyser);          // tap the output (a side branch)

const data = new Uint8Array(analyser.fftSize);
function draw() {
  requestAnimationFrame(draw);                 // loop every frame
  analyser.getByteTimeDomainData(data);        // grab the waveform
  ctx2d.clearRect(0, 0, w, h);
  ctx2d.beginPath();
  data.forEach((v, i) => {
    const x = (i / data.length) * w;
    const y = (v / 128) * (h / 2);             // 128 = the centre line
    i ? ctx2d.lineTo(x, y) : ctx2d.moveTo(x, y);
  });
  ctx2d.strokeStyle = "#00ff88";
  ctx2d.stroke();
}
STEP 07

Everything at once — the homepage engine

Now stack it all: the chord + a quiet noise layer → shared lowpass filter → master gain → speakers, with the analyser feeding the scope and your mouse driving the filter. This is, in miniature, exactly what runs on the homepage.

That's the entire concept. From here the creative directions are: a generative note sequencer (melody), reverb/delay (space), scroll- or section-reactive moods, a shareable URL "seed" (a reproducible score), or mic input so the page literally listens back.
